# Rubik's Cube Solver AI — Final Report

All numbers below are read directly from the JSON files in `benchmarks/` (`basic.json`, `with_dataset.json`, `strong.json`, `long.json`), produced by `benchmark.py` and `benchmark_strong.py`.

## Setup

- Architecture (both runs): `[324, 256, 256, 18]` — same network, same hyperparameters. Only the training data changed.
- Baseline (8k generated scrambles, lengths 1-6): 8k generated scrambles, 5 epochs.
- With dataset (120k generated scrambles, lengths 1-6): 120k scrambles, 12 epochs.
- Evaluation (identical for both): 400 fresh scrambles per length for move accuracy (lengths 1–8), 40 greedy solves per length for end-to-end solving (lengths 1–6), fixed seed 424242.

## Findings

- Both models are perfect on single-move scrambles (100.0%). The task is easy there.
- The dataset is the whole difference: 15x more training samples (8k → 120k) at the same architecture lifted 4-move accuracy 54.5% → 84.2% (+29.8 pp).
- End-to-end solving improved most on medium scrambles: 3-move success 80.0% → 100.0%, 6-move success 5.0% → 55.0%.
- Average moves to solve drop sharply, so the improved model wastes far fewer actions before reaching a solved state.
- Longer scrambles (7–8 moves) remain weak because the network was only trained on scrambles of length 1–6; accuracy there is extrapolation.

## Stronger ML model (300k samples, lengths 1–20)

- Same evaluation set for both: mean greedy solve success over lengths 1–20 went 28.7% → 31.2% (+2.5 pp).
- Biggest gains are on medium scrambles where the short-range model was extrapolating:
| Length | Old model | Long-range model |
|---|---:|---:|
| 6 | 35.0% | 55.0% |
| 7 | 35.0% | 50.0% |
| 8 | 25.0% | 35.0% |
| 9 | 0.0% | 10.0% |

- A Kociemba-distilled model and top-3 lookahead were also tried; both were weaker than plain greedy with the long-range model (see `benchmarks/strong.json`).
- A visited-state guard now prevents greedy loops (F2, F2, ...). All benchmarks above were regenerated with that fix; mean success rose from 30.2% to 31.2% for the long-range model.

## General solver and visual GUI

- The app uses the ML model as a fast path. If greedy ML stalls, it falls back to Kociemba's two-phase solver, which solves any valid cube in about 20 moves. The GUI shows every intermediate state so you can follow the moves on a real cube.
- The camera flow detects each face's 3x3 grid with OpenCV and Lab color matching; every sticker can be corrected by clicking before solving.

## Honest limitations

- The neural network alone is not a general solver. Correctness on arbitrary cubes comes from the Kociemba fallback, not from the learned model.
- When the ML model stalls (all candidate moves revisit known states), the app falls back to Kociemba; correctness does not depend on the model.
- Camera detection needs decent light and manual correction of misread stickers.
- Data is synthetic and generated by this repo's own cube simulator; the self-test in `cube.py` verifies all 18 move permutations and their inverses.

## Reproduce

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python cube.py
.venv/bin/python train.py --samples 8000 --epochs 5 --out models/model_basic.npz
.venv/bin/python benchmark.py --model models/model_basic.npz --out benchmarks/basic.json --label baseline --dataset '8k generated scrambles, lengths 1-6'
.venv/bin/python make_dataset.py --samples 120000 --out data/cube_dataset.npz
.venv/bin/python train.py --dataset data/cube_dataset.npz --epochs 12 --out models/model_dataset.npz
.venv/bin/python benchmark.py --model models/model_dataset.npz --out benchmarks/with_dataset.json --label 'larger dataset' --dataset '120k generated scrambles, lengths 1-6'
.venv/bin/python make_long_dataset.py
.venv/bin/python train.py --dataset data/long_dataset.npz --hidden 512,256 --epochs 8 --batch 512 --out models/model_long.npz
.venv/bin/python benchmark_strong.py --old models/model_dataset.npz --new models/model_long.npz --out benchmarks/long.json
.venv/bin/python make_report.py
.venv/bin/python verify.py
.venv/bin/python tests/test_gui.py
.venv/bin/python tests/test_ml.py
.venv/bin/python server.py   # GUI at http://127.0.0.1:8000
```
